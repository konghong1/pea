## 视频生成报错 `AttributeError: 'OpenAICompatibleProvider' object has no attribute '_submit_video_only'`
- **根因（源码 bug）**：`services/generation-orchestrator/app/agnes_provider.py` 里 `OpenAICompatibleProvider` 类在 line 319（`_build_image_result`）就收尾；后面整段视频方法（`_build_video_payload` 381、`_submit_video_only` 436、`_query_video_status_raw` 479、`_generate_video` 510，外加文本方法 `_generate_text`/`_generate_text_async`）掉到了**模块级游离**（带 `self` 形参但没挂到类上）。`provider_adapter.AgnesAdapter.submit` 用 `self._real._submit_video_only(...)`（`self._real` 永远是 `OpenAICompatibleProvider`）→ 实例调不到 → AttributeError。
- **修复**：把 `_ensure_http_refs_for_video`(321–377，模块级 helper，被 line 410 无 `self.` 调用)挪到类之后，让类体 206–584 连续；视频/文本方法重新挂回类（def 缩进 4 = 类成员级，非 8）。
- **⚠️ 缩进坑**：类方法 def 必须是 indent 4（与 `__init__`/`generate` 同级）。我一度误加成 indent 8，结果被 Python 当成 `_build_image_result` 方法体内的嵌套函数（AST 看不到、语法却合法）。用 `ast.parse` + 列 `it.lineno` 最可靠，比 py_compile 更能暴露"游离/嵌套"问题。
- **⚠️ 镜像烤死**：容器 `Mounts:[]`，源码无挂载，跑的是旧镜像。改完源码必须 `docker compose up -d --build generation-orchestrator` 重建镜像才固化（单纯 restart 用旧镜像会回退）；`docker cp` 仅能临时修运行中的容器。orchestrator.Dockerfile 把 `services/generation-orchestrator/` 拷进 `/app`。
- **验证**：AST 确认类含全部视频方法 → `py_compile` 通过 → 新容器探针 `hasattr(inst,'_submit_video_only')=True` → 启动日志无 AttributeError/traceback。
