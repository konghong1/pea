## 启动排错(续) — 用户 up.bat 访问不到页面
- 现象: 用户双击 up.bat 后浏览器访问不到页面。
- 根因链: ① up.bat 是前台 `docker compose up --build`, 若窗口被关 bff/web 只到 `Created`(未 start)→ 访问不到; ② **bff 宿主机 4000 被 WorkBuddy 自带 node 占用(PID 34492, 路径 C:\Users\admin\.workbuddy\binaries\node\versions\22.22.2\node.exe)** → bff bind 失败 → web 依赖 bff 也起不来; ③ web 端口此前因 8080 被占(PID 6992)已改 8088:80。
- 修复: bff 映射 4000:4000 → `4100:4000`(容器内仍 4000, nginx 反代 `bff:4000` 内网不受影响); 用 `docker compose up -d` 后台拉起, 不依赖 bat 窗口; `docker-compose.yml` 加 `name: pea-server` 固定 project name(消除 `2b4ce94e001f_*` 哈希前缀孤儿容器 + 重建冲突); `up.bat` 加 `set COMPOSE_PROJECT_NAME=pea-server` 兜底。
- 验证: web :8088 HTTP 200; web→bff `/generation/jobs` 401(反代通, 非 502); bff :4100 401。
- 访问地址: **http://localhost:8088**(不是 8080)。bff 在 4100(非 4000)。
- 教训: 绝不杀 WorkBuddy 自带 node(那是运行环境); 端口冲突一律改映射避开; 前台脚本窗口关闭会停服务, 建议用 `start.cmd`(后台) 或 `docker compose up -d`。
