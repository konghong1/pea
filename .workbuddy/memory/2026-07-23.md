## 启动排错(续) — 用户 up.bat 访问不到页面
- 现象: 用户双击 up.bat 后浏览器访问不到页面。
- 根因链: ① up.bat 是前台 `docker compose up --build`, 若窗口被关 bff/web 只到 `Created`(未 start)→ 访问不到; ② **bff 宿主机 4000 被 WorkBuddy 自带 node 占用(PID 34492, 路径 C:\Users\admin\.workbuddy\binaries\node\versions\22.22.2\node.exe)** → bff bind 失败 → web 依赖 bff 也起不来; ③ web 端口此前因 8080 被占(PID 6992)已改 8088:80。
- 修复: bff 映射 4000:4000 → `4100:4000`(容器内仍 4000, nginx 反代 `bff:4000` 内网不受影响); 用 `docker compose up -d` 后台拉起, 不依赖 bat 窗口; `docker-compose.yml` 加 `name: pea-server` 固定 project name(消除 `2b4ce94e001f_*` 哈希前缀孤儿容器 + 重建冲突); `up.bat` 加 `set COMPOSE_PROJECT_NAME=pea-server` 兜底。
- 验证: web :8088 HTTP 200; web→bff `/generation/jobs` 401(反代通, 非 502); bff :4100 401。
- 访问地址: **http://localhost:8088**(不是 8080)。bff 在 4100(非 4000)。
- 教训: 绝不杀 WorkBuddy 自带 node(那是运行环境); 端口冲突一律改映射避开; 前台脚本窗口关闭会停服务, 建议用 `start.cmd`(后台) 或 `docker compose up -d`。

**实现**：
- **删除 `<Inspector />` 在 CanvasEditor 中的引用**（import + render 都删）——"选中一个节点以查看/编辑属性" 占位彻底没了。
- **`AgentPanel` 从 CanvasEditor 内部移到 Workspace**（与 CanvasEditor 同级，位于 `<div className="relative flex-1 overflow-hidden">` 内），其 `position:absolute; right:0; width:380px` 真正落在屏幕最右。之前放在画布内 `position:absolute` 相对于 `flex-1` 内层，画布被裁切就看不到。
- **新增 `NodeChatPrompt.tsx`**：选中单个节点时在节点正下方水平居中浮现紧凑聊天框（节点标签 + 输入 + 发送按钮）；提交后调 `useAgent.push` 推消息 + `setOpen(true)` 自动展开右侧聊天面板；若是 generate 节点提示词同时回写到 `node.prompt`。随 `useViewport()` 跟随平移缩放重定位。
- `styles/index.css` 新增 `.node-chat-prompt` 一套样式（深色胶囊、圆形发送按钮、Enter 提交、Escape 清空）。

**坑**：`NodeChatPrompt` 最初用 `selectedIds.length === 1` 判定选中，结果新加节点不显示 —— `canvas.ts` 的 `addNode` 只写 `selectedId` 不写 `selectedIds`！修正：取 `selectedIds.length===1 ? selectedIds[0] : selectedId`，并以后者兜底。

**真机 E2E**：`verify/verify_ui_redesign_v2.py` 全绿：panel right edge gap=0px、宽=380px、chat-prompt top 668 > node bottom 606 且水平居中、Escape 后 chat-prompt 自动消失。TOTAL console errors: 0。截图：`verify/shots/uir2_0{1..7}.png`。

**复用要点**：右浮层要确保 positioned 父容器是页面级而不是局部 flex；store 写入要保持双字段一致（selectedId + selectedIds）否则派生组件会失效；浮层定位用 `useViewport` + `getBoundingClientRect` 而非靠 transform-only。

### 19:00 ReactFlow 自带 Controls 移除 + 自定义缩放 + 连线修复（用户第三轮反馈）
- **用户原话**：左下角 +- 缩放 + 🔒 锁图标没去掉；画布的放大缩小也没加上；"节点之间连线连不上"；"通过测试证明告诉结果，而不是随便说改好了"。
- **真 bug（连线连不上）根因**：ReactFlow 的 Handle 组件默认 `pointer-events: none`，事件穿透到 node container。ReactFlow 的 useDrag (d3-drag) 在 mousedown 时通过 `elementsFromPoint` 探测 handle；但 mousemove 中 d3-drag 会用当前 target 重新判断 isDraggable —— 当鼠标从 handle 移到 node body 时，node drag 被启动（dragging 类出现），但 connection line 没出现。这是 ReactFlow 11 的内部行为，不是配置问题。
- **修复**：在 PeaNode.tsx 用 `<span>` 包住每个 Handle，在 wrapper 上 `onMouseDown={(e) => e.stopPropagation()}` + `onPointerDown` + `onClick`，把 handle 区域的事件完全屏蔽冒泡到 node。这样 mousedown/move 期间 ReactFlow 始终把 target 视为 handle，connection 正常启动。Handle 自身的 onPointerDown 由 ReactFlow 内部接管，stopPropagation 不会影响。
- **handle 默认可见性**：之前 opacity:0 隐藏手柄，导致用户根本不知道有连节点入口。改为默认 10px 灰色圆点（opacity:1, pointer-events:all），hover/选中时放大到 22px 显 + 号。这样视觉提示 + hit 区都有了。
- **左下角 Controls 移除 + 自定义缩放**：删除 `<Controls />`，新增 `<ZoomControls />` 组件放在画布右下角（left:20px bottom:20px 避开聊天面板）：圆角胶囊容器 + 3 个圆形按钮（缩小/适配/放大）+ 当前 zoom % 读数。用 `useReactFlow().zoomIn/zoomOut/fitView`。fitView 限制 `maxZoom:1` 否则初次加载缩放到 maxZoom=3 后续放大按钮无效。
- **节点不重叠**：`add` 函数循环检查 anchor 位置是否与已有节点矩形相交，若重叠就向右下偏移 40*step, 30*step。
- **验证脚本** `verify/verify_zoom_and_connect.py` 6/6 PASS：
  - T1: `.react-flow__controls` count=0
  - T2: `.pea-zoom-controls` count=1
  - T3: handle 默认 10px 可见
  - T4: 拖动 source handle → target handle 创建 1 条边（修复前为 0）
  - T5: 放大按钮 zoom 1.0 → 1.44
  - T6: 0 console error
