## 1. 电商套图生成 403 错误修复

### 问题分析

**现象**：用户在电商套图页面点击「立即生成」时，请求返回 403 Forbidden 错误。

**根本原因**：前端模型选择器未过滤用户无权使用的模型，导致用户选择了需要更高权益等级的模型，后端在受理时抛出 403。

#### 数据库模型配置

| id | model_name | min_plan_level | is_default |
|---|---|---|---|
| agnes-image-2.0-flash | agnes-image-2.0-flash | 0 | 1 |
| agnes-image-2.1-flash | agnes-image-2.1-flash | 1 | 0 |

#### 后端权限校验逻辑

`models.service.ts:207-211`:
```typescript
if (ctx.effectivePlanLevel < model.min_plan_level) {
  throw new ForbiddenException(
    `该模型需要更高套餐 (需权益等级 ${model.min_planLevel}, 当前 ${ctx.effectivePlanLevel})`,
  );
}
```

### 修复方案（第一次迭代：隐藏无权模型）

**文件**: `pea-server/web/src/components/ecom/galleryApi.ts`

```diff
  for (const m of models) {
-   if (!m.enabled) continue
+   // 过滤掉禁用或无权使用的模型，避免用户选择后触发 403
+   if (!m.enabled || !m.allowed) continue
    const pid = Number(m.providerId)
    // ...
  }
```

### 验证结果

✅ **修复验证通过**：
- 前端只显示 `allowed=true` 的模型
- 默认模型 `agnes-image-2.0-flash` 的 `minPlanLevel=0`，所有用户可用
- 生成任务正常受理，不再报 403

## 技术要点

### 权限模型设计

- **minPlanLevel**: 模型最低权益等级要求（0=免费可用，1=基础套餐，2=高级套餐）
- **effectivePlanLevel**: 用户生效权益等级（套餐过期回落为 0）
- **allowed**: `effectivePlanLevel >= minPlanLevel` 的计算结果，前端应据此控制 UI 状态

### 用户体验优化

- **可见性**：所有模型都应该显示，让用户知道有哪些选择
- **可用性**：无权模型置灰且不可选择，避免用户误操作
- **引导性**：鼠标悬停显示所需权益等级，引导用户升级套餐

### 弹出框交互设计

- **间距统一**：所有弹出框使用相同的 gap 值（8px），保持视觉一致性
- **点击外部关闭**：提升用户体验，符合常见交互习惯
- **Escape 键关闭**：提供键盘快捷方式，提升可访问性

## 4. 弹出框间距彻底统一（bottom 定位）+ 点击输入框关闭 —— 第四次迭代，真机验证 PASS

### 根因（第3次迭代未真正解决）
- 第3次用 `top = anchorBottom - popupHeight - gap` 反推位置，但 `popupHeight` 是**预估高度**，与实际渲染不符 → 实际间距 = gap + (预估−实际)。比例弹窗预估 260 / 实际 ~233 → 实测 37px；模型弹窗预估 223 / 实际 ~223 → 9.7px；数量弹窗 CSS `bottom: calc(100%+8px)` 基准是按钮顶边 → 32px。**三者不一致**，用户明确反对。
- 点击输入框(textarea) 不关闭弹出框：textarea `onMouseDown` 有 `e.stopPropagation()`，事件不到达 window，`onDoc` 关闭监听器不触发。

### 修复（NodeChatPrompt.tsx + index.css）
1. `usePopupPosition` 改用 **bottom 定位**（弹窗底边 = 按钮底边 − gap），间距恒为 10px 与预估高度无关；返回 `{left, top, bottom, placement}`，上方 `top='auto'; bottom=vh-(anchorBottom-gap)`，下方 `top=anchorBottom+gap; bottom='auto'`；`gap=10`。
2. ModelPickerPopup / AspectPickerPopup 的 style 用 `pos.top` + `pos.bottom`。
3. textarea `onMouseDown`：先 `setPickerOpen/AspectOpen/CountOpen(false)` 再 `e.stopPropagation()`。
4. index.css `.node-count-btn-dropdown { bottom: 10px; }`（去掉 `calc(100%+8px)`，统一以按钮底边为基准）。

### 真机验证（verify/verify_popup_fixes.py, Playwright）
- model_gap=10.0 / aspect_gap=10.0 / count_gap=10.0 → 间距一致 ✅
- 点击输入框(textarea) 关闭 ✅；点击画布空白 关闭 ✅
- 电商套图模型下拉：3 选项全显示，1 个无权(agnes-image-2.1-flash)置灰(disabled) ✅
- 总体 ✅ PASS

### 经验沉淀
- 固定定位弹出框别用「预估高度」反推 top；用 bottom 定位或 `translateY(-100%)` 间距才恒定。
- 凡用 stopPropagation 的元素若属「点外部应关浮层」区域，须先手动关浮层再 stopPropagation，否则 window 监听器收不到。
- Playwright 验证：`Escape` 会触发画布 clearSelection 隐藏输入框；关闭弹窗应「再点同触发按钮 toggle」保持选中。被弹窗覆盖的元素用 `dispatch_event('mousedown')` 验证逻辑、用明确不被覆盖坐标验证外部点击。
