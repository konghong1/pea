## 注册 500 根因与根治（Senior Developer 介入）
- **现象**：`http://localhost:8088/auth/register` 注册报 500 "internal error"（BFF 4100 同样 500；web 8088 是用户入口）。
- **根因**：Docker 持久卷 DDL 陷阱——运行库 `ledger_entries.type` 枚举实际为 `('preauth','confirm','refund')`，缺 `'grant'`；而 `services/bff/src/modules/auth/auth.service.ts` 注册时插 `type='grant'` 开户赠金流水 → 枚举越界 500。源码 `infra/mysql/init/01-schema.sql` 已含 `'grant'`，但 named volume 不重跑 initdb.d，DDL 漂移未自愈。
- **止血**：运行库 `ALTER TABLE pea.ledger_entries MODIFY COLUMN type ENUM('grant','preauth','confirm','refund') NOT NULL;`（已执行）。真机验证经 8088 与 4100 注册均返回 201 + JWT。
- **根治（T-OBS-04 落地）**：
  - 新增 `pea-server/infra/mysql/assert-migrated.sh`：幂等自检，等待 MySQL→断言 `ledger_entries.type` 含 `'grant'`→缺失则自动 ALTER。
  - `docker-compose.yml` 加 `dbmigrate` 一次性服务（mysql:8.0 跑脚本后退出，`restart:no`），`bff`/`generation-orchestrator` 的 `depends_on` 加 `dbmigrate: condition: service_completed_successfully`。
  - 验证：① 已正确态下跑 dbmigrate→检测 OK 退出 0；② 独立测试表（缺 grant）跑脚本→FIX 分支自动修复枚举；③ 漂移模拟因已有 grant 数据被 MySQL 拒绝（印证问题真实性）。
- **团队提升要点**：DDL 变更必须同步更新 `01-schema.sql` 与 `assert-migrated.sh`，靠护栏自愈而非手动 ALTER；BFF 应返回结构化错误而非裸 500（见下方）。
