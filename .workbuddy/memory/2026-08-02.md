## 新建组 UI 细节修复（三次修正）

### 问题 1：新建组外层出现直角框（真正原因）
- **现象**：点击新建组后，外层有一个深色直角边框，与内部 `.pea-group-node` 的圆角框形成「两个框」。
- **根因**：ReactFlow 默认样式 `.react-flow__node-group` 自带 `border: 1px solid #1a192b; border-radius: 3px;`，项目未覆盖，导致 wrapper 泄漏出直角边框。
- **修复**：
  - `pea-server/web/src/styles/index.css` 新增覆盖规则：`.react-flow__node-group` 的 `padding/border/background/box-shadow` 全清，圆角统一为 18px。
  - 回退第一次误改：`.pea-node-image.pea-node-has-media .pea-node-body-card` 圆角恢复为 16px。

### 问题 2：切换背景按钮色块改为可见的颜色环
- **现象**：切换背景按钮中的色块为实心圆点，用户希望是“圆型中能看到颜色的环”。
- **修复**：
  - `GroupNode.tsx`：新增 `swatchRingColor()`，把背景色的 alpha 提升 4 倍（最高 0.9），让颜色能被看见。
  - `GroupNode.tsx`：通过 CSS 变量 `--pgn-swatch-color` 注入色环颜色。
  - `index.css`：`.pgn-color-swatch` 使用 `border: 3px solid var(--pgn-swatch-color)` + 透明中心，形成颜色环。

### 问题 3：去掉外层框后 group 边界看不清（三次修正）
- **现象**：去掉 ReactFlow 外层直角框后，用户反馈不知道 group 范围在哪。
- **根因**：`.pea-group-node` 原本背景透明 + 边框极淡（暗色 rgba(255,255,255,0.08)），且 `GroupNode.tsx` 对 transparent 状态仍写了内联 `background: transparent` 覆盖 CSS；headless 测试/未初始化主题时 html 无 `.light` 类但 body 已是浅灰背景，暗色白色边框更看不清。
- **修复**：
  - `GroupNode.tsx`：`bgColor === 'transparent'` 时不再写内联 background，让 CSS 默认背景/边框生效。
  - `index.css`：`.pea-group-node` 增加淡淡背景填充 + 更明显边框：
    - 暗色：`background: rgba(255,255,255,0.06)`、`border: rgba(255,255,255,0.30)`
    - 亮色 / `prefers-color-scheme: light`：`background: rgba(240,242,245,0.95)`、`border: rgba(0,0,0,0.24)`
  - 选中态增强：蓝色边框 + 内发光 + 外发光。
  - 新增 `@media (prefers-color-scheme: light)` 兜底，防止系统浅色但 html 未挂 `.light` 类时边框不可见。
- **验证**：`npm run build` 通过；新增 `verify/_check_group_default.py`，截图：`shot_group_default.png`（默认边界可见）、`shot_group_selected.png`（选中蓝色高亮）；原有 `verify/_check_group_ui_fix.py` 验证颜色环。

## storage.py 死锁修复（视频/图像终态"转存"真实缺陷）

### 根因（续前轮 probe6 定位）
- `services/generation-orchestrator/app/storage.py` 第 30 行：`_init_lock = threading.Lock()` ❌ 非可重入
- `_ensure_bucket()` 持 `_init_lock` → 调 `_do_ensure_bucket()` → `_get_client()` 在 `_client is None` 时**再次 `with _init_lock`** → 同线程自死锁
- 生产中被掩盖：worker 启动时已先行 `_get_client()` 把 `_client` 建好，使 `_ensure_bucket` 路径不再二次取锁。任何"store_bytes 先于 `_get_client`"的冷路径（终态闭环验证 / 首次转存）必挂。

### 修复（已落地 + 重启验证）
- 改为 `_init_lock = threading.RLock()`（可重入），并补注释说明机理
- `docker cp` 进容器 `pea-server-generation-orchestrator-1:/app/app/storage.py` + `docker compose restart generation-orchestrator`
- `verify/verify_minimax_finalize_closure.py` 重跑 → **PASS 转存+写库闭环**：
  - rehost → `/media/gen/videos/1/2026/08/02/<hash>.mp4`（自有稳定 CDN，非外部临时 URL）
  - finalize_job → status=done，result_json.url = 上述自有 URL
- 结论：终态链上"OUR 侧"（转存 MinIO + 写库 done）已确证可用；仅外部 succeeded→download_url 受账户余额挡（见下）

## v8 修复：生成过程中提示词消失（彻底修复）

### 用户反馈
- 点击生成时，正在生成的过程中，**输入框里的提示词文字消失了**
- 截图确认：输入框显示 placeholder（空状态），说明 contenteditable 内容被清空
- "怎么又不显示我写好的提示词了。早上不是改好了？？"

### 根因分析（深度调试定位）

通过 Playwright 自动化测试 + DOM 探针精确定位：

1. **`isUploadedMedia` 检查导致编辑器被卸载**（核心根因）
   - `NodeChatPrompt.tsx` 第 678-683 行定义了 `isUploadedMedia` 变量
   - 条件：`kind=图片/视频 && !generating && 无结果 && 有fileKey`
   - 第 1186 行 early-return：`if (!sel || !single || isUploadedMedia || !anchorEl) return null`
   - **问题场景**：用户上传了图片/视频（`fileKey` 存在）→ 输入提示词 → 点生成
     - 在 `submit()` 执行过程中，任何导致 re-render 的时刻只要 `generating=false` + `fileKey` 存在 + 无结果
     → `isUploadedMedia=true` → **整个 NodeChatPrompt 组件返回 null 被卸载** → 提示词丢失

2. **v7 的 `!generating` 守卫不够**
   - v7 只加了 `!data?.generating` 防止**生成中**隐藏
   - 但**生成前**（用户刚输入完、还没点生成，或 submit 刚开始执行时）`generating=false`
   → 如果此时有 fileKey + 无结果，编辑器仍会被隐藏
   - 更严重的是：即使之后 `generating=true` 让编辑器重新挂载，**内容已经丢了**

### 修复方案：完全移除 isUploadedMedia 隐藏逻辑

**修改文件**: `NodeChatPrompt.tsx`

```diff
- // isUploadedMedia 仅对「已完成上传且无生成结果」的节点隐藏编辑框
- // 生成中（generating=true）必须强制显示...
- const isUploadedMedia =
-   (kind === 'image' || kind === 'video') &&
-   !data?.generating &&
-   !data?.resultUrl &&
-   !(data?.resultUrls?.length) &&
-   !!data?.fileKey;
+ // 编辑框始终对选中的图片/视频节点显示（即使已上传原始素材）
+ // 用户可能想基于上传的图片/视频进一步生成（图生图/视频风格化等）
+ // 隐藏编辑框会导致输入的提示词在状态切换时被卸载丢失

  if (!sel || !single || isUploadedMedia || !anchorEl) return null;
+ if (!sel || !single || !anchorEl) return null;
```

### 为什么这个修复是正确的
- 上传态的视觉区分由**节点卡片内部**的上传预览/功能条承接
- 不应由输入框的显隐控制
- 用户上传图片后很可能想"图生图"或"视频风格化"，需要输入框来写提示词
- 即使是纯上传展示用途，隐藏输入框也比丢失用户数据更好

- `docker compose build --no-cache web` 成功
- JS 产物中 `isUploadedMedia` 引用数: **0**（完全清除）
- early-return 只剩: `if (!sel || !single || !anchorEl) return null`

### 测试验证
- Playwright 测试确认：
  - 无 fileKey 节点：输入→生成→内容保留 ✅
  - 有 fileKey 节点：v7 修复后仍会隐藏（`!generating` 守卫不足）→ v8 彻底移除后不再隐藏 ✅

4. 退出再进（`openCanvas` 重载）→ 内存空 + localStorage 空 + 后端 `editorText` 空 → 空白。

2. **NodeChatPrompt.tsx `submit()`**：仅在 `saveCanvasNow()` 返回 true 时才 `localStorage.removeItem(draftKey)`；失败则保留草稿（编辑器挂载还原优先级已含 localStorage 草稿，重进可恢复）。
