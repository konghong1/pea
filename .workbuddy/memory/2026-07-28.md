## 画布 Ctrl+滚轮触发浏览器整页缩放（修复+已验证）
- 现象：进入画布后 Ctrl/⌘ + 滚轮缩放，触发的是**浏览器整页缩放**，而非画布缩放。
- 根因：`CanvasEditor` 的 ReactFlow 开了 `panOnScroll`（普通滚轮平移画布），Ctrl+滚轮本应让画布缩放，
  但浏览器会在事件冒泡到画布逻辑前于页面层级捕获 Ctrl+wheel 并放大整页，ReactFlow 的缩放手势被"抢走"。
- 修复（`web/src/components/CanvasEditor.tsx`，Flow 组件内）：给画布容器 `flowRef`（`.pea-canvas-flow`）挂一个
  **非 passive** 的 `wheel` 监听，当 `e.ctrlKey || e.metaKey` 时 `e.preventDefault()` 阻止浏览器默认缩放；
  **不** stopPropagation，故 ReactFlow 内部 wheel 监听仍收到事件、继续完成画布缩放。普通滚轮不拦截，保留 panOnScroll 平移。
- 验证：写 `verify/verify_ctrl_wheel_zoom.py`（Playwright + dev hooks 注入，离线可跑）3 项全过：
  ① 合成 Ctrl+wheel 事件 `defaultPrevented===true`（= 浏览器缩放被拦截）② 真实 Ctrl+wheel 让 ReactFlow
  zoom 1.18→1.95→3.0（画布确实缩放）③ 普通滚轮 zoom 不变（平移手势未破坏）。console 0 error。
- 部署：`npm run build` 0 错 + `docker cp web/dist/. pea-server-web-1:/usr/share/nginx/html/` + `nginx -s reload`。
- 给团队的知识点：浏览器对 Ctrl/⌘+wheel 有"整页缩放"默认行为，画布类应用要缩放画布必须自己 preventDefault
  （且监听须 passive:false）；React 合成 onWheel 在部分浏览器是 passive，故必须用原生 addEventListener 挂。

## 图片生成同步阻塞 → 异步事件循环（2026-07-28 晚，已改+冒烟通过，待 docker 部署验证）
- 用户追问：① 之前说的"16 线程会阻塞"是什么 ② 图片生成是否同步等待 ③ 有没有异步方案。
- 澄清：**用户侧是异步（提交后轮询），但后端调模型的 `_generate_image` 用阻塞式 `requests.post`，跑在
  `dispatcher` 的 `ThreadPoolExecutor(max_workers=16)`（`config.dispatch_executor_workers=16`）。
  每张图占 1 线程 18~77s（晚高峰 5~10min）→ 第 17 张排队 = 头阻塞。这就是"16 线程阻塞"。**
- 异步方案已落地（用户明确"对性能好的都可以改"）：
  1. 新增 `app/async_core/engine.py`：单条常驻 asyncio 事件循环 + 共享 `httpx.AsyncClient`，
     承载所有外部模型调用；等待外部响应的 5~10min 期间协程 `await` 让出控制权 → 单线程并发上千在途请求。
     **收尾（转存下载+写库+发事件）丢到独立 `ThreadPoolExecutor(async_finalize_workers=32)`，绝不卡事件循环。**
  2. `agnes_provider.py`：`_generate_image`/`_generate_text` 抽 `_build_image_result` helper；新增

  3. `provider_adapter.py`：`AgnesAdapter.submit`/`MockAdapter.submit` 改 `async`；视频快提交在收尾线程池跑同步实现。
  4. `dispatcher.py`：删 `_executor` 固定线程池；`_execute`→`_execute_async` 协程；`dispatch` 用 `engine.schedule` 火忘式提交。
  5. `config.py`：废弃 `dispatch_executor_workers`（保留字段兼容 compose）；加
