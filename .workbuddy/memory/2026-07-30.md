## 画布连线缩放回归修复（问题1 收尾）
- 用户复测反馈：画布放大后「节点没连接上连线」「连接点跑到节点框里面」。
- 根因①（线没连框）：`PeaEdge` 用 `gap=(HANDLE_GAP+HANDLE_HALF)/zoom` 读实时 zoom 回退边端点，但 ReactFlow 的 `sourceX/targetX` 在边创建时按当时 zoom 算死、zoom 变化不重算 → 放大后边反向越过框边≈14px。修复：改恒定 `gap=HANDLE_GAP+HANDLE_HALF`（不除 zoom、去掉 `useStore`）。
- 根因②（连接点进框）：`.pea-handle` 受 ReactFlow `scale(1/zoom)` 影响，默认 `transform-origin` 在左右边缘，高倍缩放把手柄“拉”进框。修复：`index.css` 加 `transform-origin: center center !important`。
- `handleOffset` 终版 `=-(HANDLE_GAP/zClamped+HANDLE_HALF)`（HANDLE_GAP=14, HANDLE_HALF=6.5）。
- 验证：`verify/verify_three_fixes.py` 全 16 条断言 ALL PASS，含 `__peaSetZoom` 程序化 2x/0.5x 校验（连接点距框=14px 浮框外、线端点到框边 edge_dx=0）。
- 部署：`npm run build` → `docker cp dist/. pea-server-web-1:/usr/share/nginx/html/` → `nginx -s reload`。

## 多选框遮挡节点问题修复
- 用户反馈：框选多个节点后，选区框内节点信息被遮挡、看不清。
- 根因：ReactFlow 的 `.react-flow__viewport`（承载节点）是 `.react-flow__pane` 的子元素且无 z-index；`.react-flow__nodesselection`（承载选区矩形）也在 pane 内且 z-index=3，导致拖拽完成后选区层整体覆盖在节点层之上。
- 修复：`pea-server/web/src/styles/index.css` 给 `.react-flow__viewport { z-index: 4 !important; }`（高于 nodesselection 的 3、低于拖拽中 `.react-flow__selection` 的 6），保持选区矩形 `background: rgba(31,162,220,0.06)` 半透明 + `pointer-events: none`。
- 效果：选中后节点显示在选区背景之上，既能看清选区边框，又能看清节点内容；拖拽过程中 `.react-flow__selection` 仍覆盖节点，提供框选反馈。
- 验证：新增 `verify/verify_selection_visibility.py`，实际框选两个节点并截图，`after_drag_select` 中节点清晰可见；`verify_group_fix.py` 仍 PASS；`tsc --noEmit` 通过。

## 新功能：单击连接点添加并连接节点
- 需求：鼠标放在连接点上，或连接点跟随鼠标时，单击（非拖拽）即可添加节点。
- 实现（`CanvasEditor.tsx`）：复用既有 `edgeMenu`+`addConnectedAt` 机制。`onConnectStart` 记录起点坐标与 `handleType`；`onConnectEnd` 用位移阈值(<6px)区分「单击」与「拖拽连线」——单击(且未释放在其它节点上)→ `setEdgeMenu` 弹出"新建并连接"菜单；菜单选类型后 `addConnectedAt` 建节点并按方向连边。
- 方向：单击 source(out) 连接点→新节点作下游(source→newId)；单击 target(in) 连接点→新节点作上游(newId→source)。新节点按方向偏移出原节点外侧(±280px 屏素)避免压住。
- 兼容：拖拽连线到其它节点→连到 'in'；拖拽释放到空白→菜单(落点为新节点位置)——两个旧分支保留且重构。
- 验证：`verify/verify_click_add_node.py` 场景1(光标放圆点单击)+场景2(连接点跟随鼠标时单击) 全 7 断言 PASS（n1→n2、n1→n3 成功建连）；`verify_three_fixes.py` 回归全 19 断言 PASS（拖拽连线/缩放/框选/打组无回退）。已构建部署。
- `addConnectedAt` 新增 `handleType` 形参；`edgeMenu` state 扩为 `{x,y,sourceId,handleType,spawn}`（spawn=新节点落点，x/y=菜单锚点）。

## 选区框不可见 + 打组后 Delete 白屏崩溃修复
### 问题1：选区框在浅色背景下不可见
- **根因**：`.react-flow__selection` / `.react-flow__nodesselection-rect` 的 `background: rgba(31,162,220, 0.06)` 透明度太低（仅6%），在白色/浅色画布背景上几乎不可见；边框仅1px也不够明显。
- **修复**（`web/src/styles/index.css`）：background 提升至 `0.10`（10%），border 加粗至 `1.5px`，确保浅色/深色背景均清晰可辨。

### 问题2：打组后按 Delete 键白屏崩溃
- **根因**：`removeNode()` 删除组节点时，未清理子节点的 `parentNode` 引用。子节点仍持有 `parentNode: <已删除groupId>` + `extent: 'parent'`，ReactFlow 渲染时按 parentNode 查父节点找不到 → 抛异常/白屏。
- **修复**（`web/src/store/canvas.ts` `removeNode`）：
  - 检测目标节点是否为 `type: 'group'`，若是则从 `data.childrenIds` 收集子节点ID一并删除；
  - 额外防御：扫描所有 `parentNode === id` 的孤立子节点（防止 childrenIds 漏记）；
  - 用 `Set` 一次性批量删除，避免中间态崩溃。

### 附带修复：键盘 Delete 多选行为统一
- **问题**：键盘 Delete 只删单个 `selectedId`，多选状态按 Delete 只删一个节点（与工具条"删除全部"不一致）。
- **修复**（`web/src/components/CanvasEditor.tsx` 键盘监听）：当 `selectedIds.length > 1` 时，遍历删除所有选中节点。
